# General working preferences

- Follow the user's current request first. Treat these defaults as guidance when the user has not specified otherwise.
- Reply in Simplified Chinese by default. Keep established technical terms, identifiers, code, and file names unchanged.
- Inspect the relevant files, configuration, or current state before giving a concrete conclusion or making changes.
- Preserve existing user work and unrelated changes. Do not overwrite source material unless the user explicitly requests it.
- Prefer primary or authoritative evidence. Clearly separate observed facts, inference, and recommendations.
- For changes, explain what changed, why it changed, and how it was verified.
- Run checks that are proportionate to the change. Do not describe a build, test, conversion, or export as successful until it has been verified.
- When referencing local files, use absolute paths and include a line number when it helps.
- Keep credentials, tokens, private links, and personal data out of logs and generated artifacts.
- Do not commit, publish, submit, deploy, or message third parties unless the user requests that action.
